# 实习笔记

> 记录我在实习期间遇到的问题、踩过的坑、想明白的事，以及一点点积累下来的成长。

这个仓库是我的**实习工作笔记**。技术上它同时是两样东西：一个 Obsidian 笔记库，和一个 Git 仓库。

写它的初衷很简单：实习里每天都会撞上新的报错、新的概念、新的「原来是这样」。
如果不写下来，过两周就只剩一句「好像配过」；写下来，下次遇到同类问题能直接翻到答案，换新电脑也能照着抄。

---

## 记录什么

- **遇到的问题**：报错原文、当时的网络/权限/环境前提、试过但没用的办法
- **根因与解法**：为什么错，最后怎么解决的，有没有更根本的方案
- **概念补课**：当时不懂、后来查明白的东西（代理机制、认证方式、PATH、权限模型……）
- **收获与反思**：踩坑暴露出的思维习惯问题，比技术细节更值钱的部分
- **可复用清单**：下次配环境/接项目时可以直接照抄的步骤

## 不记录什么

- 公司内部资料、业务数据、客户信息
- 任何密钥、token、密码、内网地址
- 别人的隐私与评价

这个仓库未来可能会公开，所以上面这些一律不进来。

## 笔记约定

每篇笔记尽量包含这几块，方便日后自己回看：

1. **背景**：什么场景、什么机器、什么前提（网络、权限、版本）
2. **问题**：报错原文，不要转述
3. **根因**：为什么会出现
4. **解法**：可复制的命令或步骤，以及验证方法
5. **收获**：这件事改变了我的什么判断

命名用 `实习第N天.md`；单篇文章里如果内容跨度大，就用小节标题分区，不改文件名。

标签方面暂时只用 Obsidian 的行内标签（`#环境配置`、`#网络`、`#踩坑`），不引入复杂的 tag 体系。

## 怎么用

**看笔记**：用 [Obsidian](https://obsidian.md/) 打开这个文件夹作为库即可；不带 Obsidian 也能直接用任意 Markdown 编辑器读。

**版本管理**：

```powershell
cd D:\doc
git add -A
git commit -m "记录：xxx"
git push
```

**换电脑**：`git clone` 下来就是完整笔记库，Obsidian 配置也在里面（工作区布局这类易变文件已忽略）。

## 关于这个仓库的起点

仓库的第一篇笔记是「实习第一天」，记录的是拿到一台全新 Windows 11 电脑后，从零把全栈开发环境配起来的全过程——包括我判断失误的几次（把装成功的 PowerToys 判成失败、验证 pip 时用了会破坏验证的参数），也一并写进去了。

留着这些失败记录，是因为它们比成功的命令更有信息量：**装环境真正难的不是敲命令，而是先摸清网络和权限这两个前提，再让每个工具用它自己认识的方式联网。**
